# @first-ch/tools-mcp

MCP server exposing [First CH Tools](https://tools.first-ch.com)' free web-tool logic — WCAG contrast, JP character/X-weight counting, WebP conversion, JSON-LD generation, llms.txt generation, encoding/line-ending conversion, Marp Markdown→slide rendering, Japanese/English test-data generation, text/code diffing, cron-expression explanation, Base64/data-URI encoding, URL query-parameter editing, HTML entity escaping/unescaping, JSON⇄YAML conversion, px ⇄ rem/em unit conversion, colour-code conversion with alpha compositing, MD5/SHA-1/SHA-256/SHA-384/SHA-512 hashing, JWT decoding with expiry and signature checks, User-Agent parsing with device/bot detection, bulk UUID v4 / ULID generation, aspect-ratio calculation with responsive sizing, case conversion between camelCase, snake_case and kebab-case, CSV/TSV ⇄ JSON conversion, IP/CIDR calculation with subnet splitting and IP-range reduction, business-day date calculation with Japanese public holidays, HTML-to-Markdown conversion, Japanese era ⇄ Western date conversion with age calculation, and URL-slug generation from Japanese titles — to AI agents such as Claude Code. All of those run on your machine.

It also ships **`app_*` tools** for the 36 web apps at [apps.first-ch.com](https://apps.first-ch.com) (site checks such as GEO/AI-search readiness, meta tags, security headers, SSL certificates, DNS and email DNS, redirects, broken links, structured data, AI-crawler access, Japanese readability, and AI-assisted business-tone and LP-copy checks). Unlike the local tools, **an `app_*` tool sends its input (a URL, domain name or text) to apps.first-ch.com** and returns the JSON the app's API responds with — see [Network access, files and privacy](#network-access-files-and-privacy).

## Install

Three ways to add this server, pick whichever fits your client.

**Requires Node.js `>=24`** (all three methods below run the server via `npx`, so Node must be installed even when the MCP client itself — e.g. Claude Code's native, no-Node install — doesn't strictly require it).

### 1. npm, via the Claude Code CLI

```bash
claude mcp add firstch-tools -- npx -y @first-ch/tools-mcp
```

### 2. Claude Code plugin (also installs the same MCP server)

```
/plugin marketplace add First-CH/firstch-tools-mcp
/plugin install firstch-tools@first-ch
```

### 3. Any other MCP client (generic JSON config)

Add to your client's server config (e.g. `mcp.json` / `claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "firstch-tools": {
      "command": "npx",
      "args": ["-y", "@first-ch/tools-mcp"]
    }
  }
}
```

This server is also registered in the [MCP Registry](https://registry.modelcontextprotocol.io) as `io.github.First-CH/tools-mcp` (see [`server.json`](./server.json)), so registry-aware clients can discover and install it by that name too.

## Network access, files and privacy

- **Local tools vs. `app_*` tools.** Every tool without the `app_` prefix runs entirely on your machine and sends nothing anywhere. **The `app_*` tools are the exception by design: each call sends its input (the URL, domain name, DKIM selector or text you pass) to First CH's server at apps.first-ch.com**, which processes it and returns the result. The apps store neither the input nor the result; the AI apps (`app_tone_check`, `app_lp_persona_check`) pass the text to Cloudflare Workers AI and keep only a per-day call count (no text, no IP) to enforce the daily cap. Like any web request, the call reveals your public IP address to apps.first-ch.com (hosted on Cloudflare); it is used only for in-memory per-IP rate limits and is not stored. The apps that check a site fetch that site from First CH's server. The User-Agent is `first-ch-tools-mcp/<version>`. Don't pass anything confidential to an `app_*` tool, and stick to the local tools when nothing may leave your machine. `FIRSTCH_APPS_BASE_URL` overrides the base URL (for testing).
- **The local tools make no network requests.** The only exceptions are `npx` downloading the package from the npm registry, and `marp_render` with `allowRemote: true` (your local Chrome/Chromium then fetches the remote images/stylesheets your Markdown references). By default `marp_render` loads no web fonts, keeps emoji as text, strips remote `@import`s from the built-in themes and runs Chrome with network access blocked and its sandbox enabled (`MARP_CHROME_NO_SANDBOX=1` opts out where the sandbox cannot start, e.g. root in a container).
- **No overwriting.** Tools that write files (`outputPath`/`outputDir`, `webp_convert`, `marp_render`) refuse to replace an existing file unless you pass `overwrite: true`. They are annotated `readOnlyHint: false` / `destructiveHint: true`; every other tool is `readOnlyHint: true`. The `app_*` tools (and `marp_render`) are annotated `openWorldHint: true` because they reach the network. `marp_render` without any path writes to `<OS temp dir>/firstch-tools-mcp/`; the server never deletes result files.
- Privacy policy: [plugins/firstch-tools/PRIVACY.md](./plugins/firstch-tools/PRIVACY.md). Bugs and questions: [GitHub Issues](https://github.com/First-CH/firstch-tools-mcp/issues).

## Telemetry

Nothing is logged by default. Usage is recorded **only** when you set the `FIRSTCH_TOOLS_USAGE_LOG` environment variable to a file path — each tool call then appends one JSON line (`{ ts, tool, source }`) to that local file. The log itself is never transmitted; if the variable is unset, no file is written. (This covers usage logging only — the `app_*` tools still send their input to apps.first-ch.com as described above.)

## Vendor sync (WebP codec)

`webp_convert` bundles a vendored, unmodified subset of [`@jsquash/webp`](https://github.com/jamsinclair/jSquash) v1.5.0 under [`vendor/jsquash-webp/`](./vendor/jsquash-webp/). The web version at tools.first-ch.com vendors the exact same v1.5.0 subset, so both surfaces produce identical output. Each side's CI independently verifies its vendored files against [`vendor/jsquash-webp/CHECKSUMS.sha256`](./vendor/jsquash-webp/CHECKSUMS.sha256) (see [`.github/workflows/ci.yml`](./.github/workflows/ci.yml)), so a silent, unnoticed drift between the two copies isn't possible.

Release rule: a push to `main` automatically publishes a new package version through npm Trusted Publishing (OIDC) after every CI gate passes. Package changes must bump every synchronized version field; if a version already exists with different package contents, CI fails instead of overwriting it. CI-only changes with identical package contents safely skip publishing.

`@first-ch/tools-mcp` は、[First CH Tools](https://tools.first-ch.com)（無料Webツール集）の計算ロジック — WCAGコントラスト比・日本語文字数/Xウェイト計測・WebP変換・JSON-LD生成・llms.txt生成・文字コード/改行コード変換・Marp Markdown→スライド レンダリング・テストデータ生成・テキスト/コード差分・Cron式の解説・Base64/Data URI変換・URLパラメータの分解/編集/再構築・HTML特殊文字のエスケープ/エンティティのデコード・JSON⇄YAMLの相互変換・px⇄rem/emの単位換算とCSSの一括変換・カラーコードの相互変換とアルファ透過の合成・MD5/SHA-1/SHA-256/SHA-384/SHA-512のハッシュ生成と照合・JWTのデコードと有効期限/署名の検証・User-Agent文字列の解析とデバイス判定・UUID v4 / ULIDの一括生成・アスペクト比の計算とレスポンシブサイズの算出・camelCase / snake_case / kebab-case などの文字列ケース変換・CSV/TSV ⇄ JSON の相互変換・日数/営業日の計算（日本の祝日を内蔵）・HTML→Markdownの変換・和暦⇄西暦の変換と満年齢の計算・日本語タイトルからのURLスラッグ生成 — をAIエージェント（Claude Code等）向けMCPツールとして提供するサーバーです。これらは全て端末内で処理します。

あわせて、[apps.first-ch.com](https://apps.first-ch.com) のWebアプリ36本（GEO・メタタグ・セキュリティヘッダー・SSL証明書・DNS／メールDNS・リダイレクト・リンク切れ・構造化データ・AIクローラー許可・和文可読性・AIによるビジネス文面/LP文言のチェックなど）を呼ぶ **`app_*` ツール**も提供します。**`app_*` ツールは入力（URL・ドメイン名・文面）を apps.first-ch.com のサーバーへ送り**、アプリの API が返した JSON を返します（端末内で完結する他のツールとはここが違います）。詳しくは [通信・ファイル・プライバシー](#通信ファイルプライバシー) を参照してください。

### インストール

導入経路は3通りあります。使っているクライアントに合わせて選んでください。

**Node.js `>=24` が必要です**（以下いずれの方法も `npx` 経由でサーバーを起動するため。Claude Code本体はNode不要のnativeインストールもありますが、その場合でもNodeは別途必要です）。

#### 1. npm（Claude Code CLI）

```bash
claude mcp add firstch-tools -- npx -y @first-ch/tools-mcp
```

#### 2. Claude Code plugin（同じMCPサーバーを導入）

```
/plugin marketplace add First-CH/firstch-tools-mcp
/plugin install firstch-tools@first-ch
```

#### 3. その他のMCPクライアント（汎用JSON設定）

設定ファイル（`mcp.json` / `claude_desktop_config.json` 等）に以下を追加します。

```json
{
  "mcpServers": {
    "firstch-tools": {
      "command": "npx",
      "args": ["-y", "@first-ch/tools-mcp"]
    }
  }
}
```

本サーバーは [MCP Registry](https://registry.modelcontextprotocol.io) にも `io.github.First-CH/tools-mcp` として登録済みです（[`server.json`](./server.json) 参照）。レジストリ対応クライアントはこの名前からも発見・導入できます。

#### apps のツール（`app_*`・apps.first-ch.com へ送信）

**既定では無効です。** 入力を apps.first-ch.com へ送るため、環境変数 `FIRSTCH_ENABLE_APPS=1` で明示的に有効にしたときだけ登録されます（例: `claude mcp add firstch-tools -e FIRSTCH_ENABLE_APPS=1 -- npx -y @first-ch/tools-mcp`）。指定しなければ、すべてのツールが端末内で動き、どこにも送信しません。

各 `app_*` ツールは、アプリ1本の公開 JSON API（`POST https://apps.first-ch.com/<slug>/api/<action>`・認証なし。一覧は [llms.txt](https://apps.first-ch.com/llms.txt)）を呼び、応答の JSON をそのまま返します。**入力は apps.first-ch.com へ送られてそこで処理され、入力も結果もサーバーには保存されません。** 対象サイトを取得するアプリは First CH のサーバーから相手のサイトへアクセスするので、相手側には apps.first-ch.com からのアクセスとして記録されます。全ての `app_*` ツールは `lang?`（既定 `ja`／`en`）で判定・エラー文の言語を選べます。待ち時間は30秒（重いアプリと AI のアプリは60秒）。入力の不備・相手サイトに届かない・回数制限などの API エラーは、アプリの `error` コードと `message` を含むツールのエラーとして返ります。

**`marp_render` のPDF出力にはローカルの Chrome/Chromium が必要です。** marp-core によるHTML生成はブラウザ非依存（`npx` 導入を軽く保つため）で、PDFはローカルインストール済みの Chrome/Chromium を headless で駆動して生成します。定番パスから自動検出し、`MARP_CHROME_PATH` で実行ファイルを明示することもできます。見つからない場合は HTML のみを返し `pdf_skipped` を報告します（そのHTMLを開いて印刷→PDF保存でも1スライド=1ページで作成できます）。

### 通信・ファイル・プライバシー

- **端末内のツールと `app_*` ツールの違い。** `app_` で始まらないツールは全て端末内で処理し、どこにも送信しません。**`app_*` ツールだけは設計上の例外で、呼び出すたびに入力（渡した URL・ドメイン名・DKIM セレクタ・文面）を First CH のサーバー apps.first-ch.com へ送り**、そこで処理した結果を受け取ります。入力も結果もサーバーには保存しません。AI のアプリ（`app_tone_check`・`app_lp_persona_check`）は文面を Cloudflare Workers AI に渡して判定し、1日の上限を数えるために日付と全体の回数だけを記録します（文面・IP は記録しません）。通常の Web アクセスと同じく、呼び出し元のグローバルIPは apps.first-ch.com（Cloudflare 上で稼働）に届きますが、IP ごとの回数制限（メモリ上のみ）に使うだけで保存しません。サイトを診断するアプリは First CH のサーバーから対象サイトを取得します。User-Agent は `first-ch-tools-mcp/<version>` です。機密の文面や社外秘の URL は `app_*` ツールに渡さず、端末の外へ出したくない入力には端末内のツールを使ってください。テスト用に `FIRSTCH_APPS_BASE_URL` で送り先を差し替えられます。
- **端末内のツールは外部へ通信しません。** 例外は起動時に `npx` が npm レジストリからパッケージを取得することと、`marp_render` に `allowRemote: true` を渡したとき（Markdown が参照する外部の画像・CSS をローカルの Chrome が読み込む）だけです。既定の `marp_render` は Webフォントを読まず、絵文字は文字のまま、組み込みテーマの外部 `@import` を取り除き、Chrome も外部通信を止めサンドボックス有効のまま起動します（サンドボックスが使えない環境だけ `MARP_CHROME_NO_SANDBOX=1` で外せます）。
- **上書きしません。** ファイルを書くツール（`outputPath`/`outputDir` を持つもの・`webp_convert`・`marp_render`）は、同名のファイルがあれば `overwrite: true` を渡さない限りエラーにします。これらは `readOnlyHint: false`・`destructiveHint: true`、それ以外は `readOnlyHint: true` を付けています。ネットワークへ出る `app_*` ツール（と `marp_render`）には `openWorldHint: true` を付けています。パス指定の無い `marp_render` は `<OSの一時ディレクトリ>/firstch-tools-mcp/` に書き、書いたファイルはサーバーが消しません。

### 計測（Telemetry）について

既定では何も記録しません。環境変数 `FIRSTCH_TOOLS_USAGE_LOG` にファイルパスを設定したときのみ、各ツール呼び出しごとに1行のJSON（`{ ts, tool, source }`）をそのローカルファイルへ追記します。この記録ファイルを送信することはありません（未設定であればファイルへの書き込み自体が発生しません）。なお、これは利用記録の話で、`app_*` ツールは上記のとおり入力を apps.first-ch.com へ送ります。

### Web版

同一アルゴリズムを、インストール不要の無料ブラウザツールとしても公開しています: **[tools.first-ch.com](https://tools.first-ch.com)**。UIで使いたいとき・MCPクライアントを持たない相手にリンクを共有したいときはこちらをどうぞ。`app_*` ツールは **[apps.first-ch.com](https://apps.first-ch.com)** のWebアプリと1対1で対応しています。

### vendor同期（WebPコーデック）

`webp_convert` は [`@jsquash/webp`](https://github.com/jamsinclair/jSquash) v1.5.0 の無改変サブセットを [`vendor/jsquash-webp/`](./vendor/jsquash-webp/) 配下に同梱しています。Web版（tools.first-ch.com）も同じv1.5.0サブセットを無改変で使っており、双方が同一の出力を返します。各リポジトリのCIが独立に、自身のvendorファイルを [`vendor/jsquash-webp/CHECKSUMS.sha256`](./vendor/jsquash-webp/CHECKSUMS.sha256) に対して検証するため（[`.github/workflows/ci.yml`](./.github/workflows/ci.yml) 参照）、両者が気づかないうちに乖離することはありません。

### 開発者向け

```bash
npm ci
npm test        # ユニットテスト（test.mjs）と、fetch を差し替えた app_* のテスト（test-apps.mjs・実ネットワークなし）
node e2e.mjs     # stdio smokeテスト: server.mjsを子プロセス起動しツール一覧取得・実行を検証（app_* は手元の偽APIへ）
```

`test-apps.mjs` は、FirstCHApps リポジトリがこのリポジトリの隣（または `FIRSTCH_APPS_REPO`）にあれば、`apps.mjs` の定義が `functions/_shared/apps-registry.ts` の一覧と一致するかも確かめます（無ければその検査だけ飛ばします）。

CIはNode 24 でのテストに加え、vendorチェックサム検証・公開tarball内容検査を実行します（[`.github/workflows/ci.yml`](./.github/workflows/ci.yml) 参照）。
